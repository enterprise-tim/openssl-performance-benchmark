# PQC Visualization Bug Fix

## Problem

The Post-Quantum Cryptography (PQC) visualization page was showing "No Post-Quantum Data Available (requires OpenSSL 3.5+)" even though:

1. The benchmark WAS collecting ML-KEM-768 data (36,763 ops/sec from OpenSSL 3.5.3)
2. The data WAS in the `summary.json` file with the correct metric name (`ml_kem_768_ops_sec`)
3. The `generate-viz-multipage.js` script WAS creating the `pqc.html` file
4. The JavaScript code in `pqc.html` was correctly looking for `ml_kem_768_ops_sec`

## Root Cause

The GitHub Actions workflow (`benchmark.yml`) was only copying `visualizations.html` to the GitHub Pages deployment, ignoring all the other HTML files generated by the multi-page visualization system:

- `index.html`
- `overview.html`
- `tls-comparison.html`
- `bellingrath.html`
- `schmatz.html`
- `mraz.html`
- **`pqc.html`** ← This file was being generated but never deployed!

The deployed site was showing an old fallback `visualizations.html` that didn't include the PQC page in its navigation.

## Solution

Updated `.github/workflows/benchmark.yml` to:

1. **Copy all HTML files** from the `results/` directory:
   ```yaml
   # Copy all generated HTML files (multi-page visualization)
   cp results/*.html release-pack/ 2>/dev/null || echo "No HTML files found"
   ```

2. **Improved fallback index.html** that redirects to the proper multi-page dashboard if the generator somehow fails

3. **Better logging** to show which HTML files are being deployed

## Verification

After this fix is deployed, the PQC page should show:
- Bar chart with ML-KEM-768 performance
- Data for OpenSSL 3.5.3: 36,763 ops/sec
- Proper navigation between all benchmark pages
